# HU-10 · Detalle de producto

## Integración con el equipo

La ruta canónica es `/producto/<slug>`. Consulta Supabase en cada petición; el
slug ya existe en la tabla y no se recalcula a partir del nombre. Los enlaces
anteriores `/products/<uuid>` redirigen permanentemente al slug del producto.
Los números de los antiguos productos de demostración no se asignan a productos reales.

La mayor parte de la implementación está en archivos nuevos:

- `src/pages/producto/[slug].astro`: página, estados HTTP y metadatos.
- `src/services/products/detail.ts`: consulta pública y disponibilidad.
- `src/components/products/detail/`: galería y contacto.
- Una migración nueva, sin modificar las migraciones existentes.
- `tests/hu10/`: pruebas aisladas de permisos, renderizado y navegador.

Solo se modifican cinco archivos existentes:

| Archivo                                     | Cambio que debe conservarse al resolver un merge                        |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| `src/components/products/ProductCard.astro` | La tarjeta enlaza a `/producto/${encodeURIComponent(product.slug)}`.    |
| `src/layouts/Base.astro`                    | `<slot name="head" />` dentro de `<head>`.                              |
| `src/layouts/PublicLayout.astro`            | Reenvío del slot: `<slot name="head" slot="head" />`.                   |
| `astro.config.mjs`                          | Orígenes autorizados para optimizar imágenes de Storage y del seed.     |
| `src/pages/products/[id].astro`             | Sustituye los datos de ejemplo por compatibilidad con la ruta canónica. |

No se modifican `.env`, `package.json`, el lockfile, el login, el panel de
administración, los tipos generados ni `ProductContact.tsx` de HU-11.
Esto reduce los puntos de conflicto; no garantiza que otras ramas no modifiquen
esas mismas líneas.

## Regla de disponibilidad y HU-11

La ficha muestra **disponibilidad**, no cantidades exactas.
Solo habilita «Me interesa» cuando `status === 'available'` y `quantity > 0`.
`sold` muestra «Vendido»; `out_of_stock` o cantidad cero muestran «Agotado».
El botón queda deshabilitado si falta `PUBLIC_WHATSAPP_NUMBER`.

`ProductInterest.astro` recibe `name`, `price`, `url`, `available` y `sold`.
Actualmente abre WhatsApp con nombre, precio en bolivianos y enlace canónico.
El equipo de HU-11 puede sustituir este componente o añadir su registro de
interés en él. HU-10 no escribe en `product_interests` ni modifica ese flujo.

## Base de datos

Aplicar `supabase/migrations/20260915181439_hu10_public_product_detail.sql` con
el procedimiento de migraciones del equipo. La política de lectura pública
permite consultar **todos los productos activos**, incluidos agotados y vendidos.
Los productos desactivados siguen ocultos; los filtros actuales del catálogo
siguen mostrando únicamente disponibles. No concede permisos de escritura.

En una base local desechable, con Docker iniciado:

```sh
bunx supabase start
bunx supabase db reset --local
```

`db reset` reconstruye la base local y repone el seed: no utilizarlo para
conservar datos locales existentes. En otros entornos aplicar la nueva migración
con el flujo de despliegue acordado, sin resetear datos.

Esta entrega no aplica cambios en la nube. La comprobación del stack local no
pudo ejecutarse porque Docker no estaba disponible. Se verificaron todas las
migraciones y el seed del catálogo en PostgreSQL aislado mediante PGlite.

## Imágenes y metadatos

- Galería adaptable, desplazamiento táctil, flechas, miniaturas y teclado.
- WebP de calidad 80, variantes de 400/640/1000 px y miniaturas comprimidas.
- Primera fotografía prioritaria; fotografías secundarias con carga diferida.
- Sin JavaScript se conserva el desplazamiento nativo de la galería.
- La página sirve título, descripción, canonical y Open Graph en el HTML del
  servidor. La primera fotografía ordenada se usa para la vista previa.
- Sin fotografías se muestra un estado alternativo; no se inventa una imagen.
- En producción los archivos y el dominio deben ser accesibles públicamente
  para que los rastreadores de WhatsApp puedan recuperar la vista previa.
- Si se usa un dominio propio de Storage, añadirlo a `image.remotePatterns`.

## Verificación reproducible

Se usan dependencias de prueba en un directorio externo para evitar modificar
el manifiesto y el lockfile compartidos. Ejemplo en PowerShell:

```powershell
$hu10Tools = Join-Path $env:TEMP 'smal-hu10-tools'
New-Item -ItemType Directory -Force -Path $hu10Tools | Out-Null
bun add --cwd $hu10Tools playwright @electric-sql/pglite
bun run build
$env:HU10_TEST_TOOLS = $hu10Tools
node tests/hu10/verify.mjs
```

Chrome se busca en su ubicación estándar de Windows; se puede indicar otro
ejecutable mediante `HU10_CHROME_PATH`. El puerto 4399 debe estar libre.
La prueba arranca y cierra su propio servidor de producción con respuestas
Supabase simuladas; no cambia `.env`, no envía mensajes, no se conecta a la base
real ni detiene el servidor de desarrollo. Las capturas se guardan en el
directorio externo de herramientas.

Cobertura: enlaces del catálogo y retorno, ruta directa, información completa,
orden y navegación de fotos, móvil, compresión WebP real, `srcset`, carga diferida,
metadatos, contacto, productos agotados/vendidos/sin stock, inexistentes/inactivos,
404, fallos de backend con 503, ausencia de fotografías y redirección por UUID.
Los permisos se comprueban por separado con evaluación real de RLS en PGlite.

`bun run build` pasa. `bun run astro check` mantiene los 14 errores previos en
Navbar, PerksMarquee, SocialTikTok y ProductFilters; HU-10 no introduce errores
adicionales. Sus correcciones quedan fuera de esta historia para evitar mezclar
trabajo de otros integrantes.
